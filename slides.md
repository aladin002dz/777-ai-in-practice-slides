- Plan: define the audience, purpose and approved facts

## 10. Better Prompts with RCTFC

- Role: who should AI act as?
- Context: who is the website for, and why?
- Task: what should AI produce?
- Format: how should the answer be organized?
- Constraints: what must AI include, avoid or verify?
- Treat RCTFC as a practical checklist; review the actual answer

## 11. From a Vague Request to a Useful Brief

- Vague: "Make me a professional website."
- Role: "Act as a website content planner."
- Context: "Use Mahfoudh Arous’s public LinkedIn profile as the source for his personal website and portfolio."
- Task: "Draft a concise one-page personal website and portfolio outline."
- Format: "Return a table of sections and suggested copy."
- Constraints: "Use only supplied facts. Mark missing information. Do not invent credentials, clients or contact details."
- Bonus — Example: "Match the tone of this short sample: [paste 2–3 lines you like]. Follow its style, not its content."

## 16. Review, Improve & Check Again

- Are all statements supported by the supplied profile?
- Is the text readable on a phone?
- Do navigation and approved links work?
- Can you move through interactive elements with a keyboard?
- Avoid private information, exposed credentials and pretend contact forms
- What would make this page more useful to its visitors?
- Request one specific revision, then repeat the affected checks

## 17. Git, GitHub & Deploying Your Website

- Git: save versions of your project locally and track changes
- GitHub: keep a project repository online
- GitHub Pages: publish a static website from a repository
- Local preview and public website are different stages
- Browser route: upload index.html and style.css -> Pages settings -> deployment status -> public URL
- Open and check the online version; a deployment attempt is not proof of success
- Protect existing websites and never upload secrets or private files
- No terminal needed for this route; use a separate project repository

## 18. Git & GitHub: Save, Share and Publish Your Code

- `git init` | Start tracking your project folder (once per project)
- `git add .` | Stage all changed files for the next save
- `git commit -m "message"` | Save a snapshot with a short description
- `git push` | Send your saved commits to GitHub
- GitHub | Hosts your code online: github.com/username/my-website
- Public URL | GitHub Pages publishes the site: username.github.io/my-website
- First push only: connect your GitHub repository with `git remote add origin <repository URL>`
